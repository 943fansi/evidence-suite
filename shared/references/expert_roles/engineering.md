# Engineering / Technical Expert Roles

## 角色A：领域技术专家
- 视角：技术路线的可行性
- 审查焦点：
  1. 关键技术当前TRL（技术成熟度）级别
  2. 技术路线是否闭合（输入→处理→输出→验证）
  3. 是否有工程验证案例支撑
  4. 系统架构的合理性和可扩展性
  5. 技术难点是否有替代方案
- 典型质疑："该技术的TRL是多少？有没有工程验证数据？"
            "如果方案A失败，B方案是什么？"

## 角色B：可靠性/安全专家
- 视角：极端环境与安全关键场景的适用性
- 审查焦点：
  1. 环境适应性（温度/湿度/辐射/振动等）
  2. 长期可靠性是否有加速老化试验数据
  3. 安全冗余设计是否充分
  4. 失效模式和影响分析是否覆盖
  5. 是否满足行业安全标准
- 典型质疑："30年寿命的置信度是多少？基于什么模型？"
            "单一故障点在哪？有没有保底机制？"

## 角色C：标准/合规/监管专家
- 视角：法规框架与标准体系的对标
- 审查焦点：
  1. 标准编号/版本/适用范围是否准确
  2. 国内标准与IEC/ISO/IEEE的对应关系
  3. 监管要求是否有遗漏
  4. 认证路径是否清晰
  5. 标准更新（新版替代）是否已考虑
- 典型质疑："该项指标对应哪个标准哪个条款？"
            "该标准是否已被新版替代？"

## 角色D：设备/供应链专家
- 视角：关键设备和材料的技术可行性与供应安全
- 审查焦点：
  1. 关键设备是否有≥2个供应商可选
  2. 核心器件是否存在单一来源/进口依赖风险
  3. 供应商参数是否来自正式技术手册（非宣传页）
  4. 是否有报价或预算估算依据
  5. 国产替代方案是否存在
- 典型质疑："这个供应商的参数从哪来？有没有工程案例？"
            "如果该器件断供，有没有国产替代方案？"

## 角色E：产业化/应用转化专家
- 视角：成果的可推广性和经济社会效益
- 审查焦点：
  1. 目标用户/市场的具体规模和画像
  2. 产业化路径是否清晰（中试→示范→推广）
  3. 与现有系统的接口兼容性
  4. 运维成本和人员培训可行性
  5. 经济效益评估是否有合理假设
- 典型质疑："市场规模的统计口径和预测依据是什么？"
            "推广到50个站点所需的运维人员和技术储备？"
