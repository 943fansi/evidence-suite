# AI / Computer Science Expert Roles

## 角色A：机器学习/算法专家
- 视角：方法选择的合理性、可复现性与有效性验证
- 审查焦点：
  1. 方法选型是否有问题约束支撑（数据规模/维度/实时性），是否跟风"先进"模型
  2. 数据集规模、标注方式、划分（train/val/test）是否明确
  3. 基线方法、消融实验、指标选择（F1/AP/PR-AUC 等）是否公平完整
  4. 超参数、随机种子、实验次数是否报告，能否复现
  5. 与经典/轻量方法对比是否有显著性与计算成本说明
- 典型质疑："这个SOTA方法在你的数据量下真的比XGBoost好？显著性检验了吗？"
            "报告AUC前，样本不平衡问题怎么处理的？"

## 角色B：系统/软件架构专家
- 视角：算法部署为系统时的工程可行性
- 审查焦点：
  1. 推理延迟/吞吐量/资源占用是否满足现场约束（边缘/云端）
  2. 数据链路（采集→预处理→推理→告警）是否闭环、延迟可量化
  3. 模型更新/在线学习/迁移到新场景的机制是否说明
  4. 系统可靠性：单点故障、降级策略、冗余
  5. 是否存在把"实验室精度"直接当作"现场性能"的过度宣称
- 典型质疑："现场采样率与告警时延下，模型还能保持声称的精度吗？"
            "换一个场地/传感器型号，模型需要重新训练多少数据？"

## 角色C：数据/隐私与安全专家
- 视角：数据合规、标注质量与安全边界
- 审查焦点：
  1. 数据来源合规性（许可、隐私、脱敏、伦理审查）
  2. 训练/测试数据是否泄漏（时间穿越、同源复制）
  3. 对抗鲁棒性、误报/漏报成本是否被考虑
  4. 模型可解释性是否满足监管/责任归属要求
  5. 涉及关键基础设施（如能源/管网）时，故障与安全责任边界
- 典型质疑："训练集和测试集有没有时间重叠导致的泄漏？"
            "告警模型的漏报代价有多大，有没有做成本加权？"

## 角色D：领域应用专家（传感/工业场景）
- 视角：与传感器/硬件/物理过程的耦合验证
- 审查焦点：
  1. 传感信号特征（采样率、信噪比、带宽）与算法输入是否匹配
  2. 现场噪声/干扰（温度、振动、地磁）对特征鲁棒性的影响
  3. 与领域物理规律是否冲突（如声波/应变传播速度约束）
  4. 是否有真实场站数据验证，而非仅仿真/公开数据集
  5. 误报率在现场运营可接受范围内吗
- 典型质疑："仿真精度拿到真实管道/堤坝现场还成立吗？现场数据是多少？"
            "信号采样率下，算法的物理分辨率足够吗？"
