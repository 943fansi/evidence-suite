# 专利申请技术交底书写作指南（Patent Disclosure Writing Guide）

> 本指南从真实发明专利交底书样本（油浸式套管不均匀老化无损评估方法）提炼，供 stage5 起草 `templates/patent_disclosure.md` 类文档时加载。目标：让产出既符合专利代理机构的交底书惯例，又保留 evidence-proposal 的证据可追溯性。
>
> 适用类型：发明专利 / 实用新型（交底书阶段）。外观设计不适用本指南。

## 一、整体结构（七节 + 表单头）

| 节 | 内容 | 篇幅占比（参考） |
|----|------|----------------|
| 表单头 | 发明创造名称、拟申请类型、申请人、发明人、联系人等行政元数据 | — |
| 1 技术领域 | 一句话定位 | ~3% |
| 2 背景技术 | 对象重要性 → 现有技术分类与局限 → 收敛句 | ~20% |
| 3 发明内容 | 1 目的 / 2 技术方案（步骤化）/ 3 效果 | ~40% |
| 4 附图说明 | 图1～图N 逐图一句标题 | ~3% |
| 5 实施方式 | 重述步骤 + 具体实施例（含验证数据）+ 兜底段 | ~34% |

## 二、各节写法规范

### 2.1 发明创造名称

命名公式：**「一种基于[技术手段A]（及[技术手段B]）的[对象][状态/性能][动作]方法/装置/系统」**。
- 技术手段写核心方法而非设备（"基于有限元分析及介电响应测试"而非"基于某测试仪"）。
- 名称即权利要求主题的雏形，技术方案各步骤必须能回溯到名称中的每个词。

### 2.2 技术领域

固定句式："本发明属于……技术领域，特别是涉及到一种……"。两句话以内，不展开论证。

### 2.3 背景技术（三段式）

1. **对象段**：技术对象是什么、在系统中承担什么功能、失效后果多严重。后果严重性必须给量级感（如"110kV及以上……事故占比较高，电压等级升高比例上升"），且此类断言须挂 `[Sx]`。
2. **现有技术段**：按技术路线分类（如在线监测 / 离线检测 / 新兴宽频技术）逐类说明原理与**固有局限**——局限必须指向本发明要解决的同一个瓶颈（样本中：单曲线只能评估"平均"老化，而决定寿命的是"局部热点"，即"不均匀"无法评估）。
3. **收敛句**："现阶段的……均无法实现……，亟需一种……的技术方案来解决这一问题。" 收敛句的问题陈述必须与发明内容的"目的"逐字呼应。

**[Sx] 处理规则（关键差异）**：专利正文是法言法语，不允许出现学术引用体系污染，但背景技术的事实性断言（事故占比、参数、现有技术原理）仍须可追溯。规则：
- 交底书阶段：背景技术断言保留 `[Sx]` 标记（可附"该数据来自……[Sx]"式括注），确保代理人核查先行技术时可直接回溯；
- 交付说明中注明：**提交专利代理前由代理人剥离 `[Sx]` 标记**，本 skill 的引用闭合校验以交底书版本为准；
- 发明内容/实施方式两节**禁止**出现 `[Sx]`——技术方案与实施例是本发明的原创内容，引用先行技术反而削弱新颖性表述。

### 2.4 发明内容（三段式）

**1 目的**："为了克服现有技术存在的不足：本发明提供一种……，用于解决……的技术瓶颈。"——一句目的句，瓶颈表述与背景技术收敛句一致。

**2 技术方案**（核心，步骤化）：
- 引导句固定："为了实现上述目的，本发明采用的技术方案是：一种……，其特征在于：所述方法包括以下步骤，并按以下步骤顺次进行："
- 步骤格式："步骤一、……；步骤二、……"。每步：
  - 以动词开头（测试 / 建立 / 构建 / 求解 / 划分）；
  - 关键参数给**范围**不给单点（"在5摄氏度至80摄氏度测试温度下"）——范围是保护范围的载体，单点值窄化保护；
  - 步骤间显式依赖（"根据步骤一获得的……"、"结合步骤三中的……"）形成可验证的依赖链；
  - 公式编号 (1)(2)(3)，每个公式后必须跟"式中，X 为……"的符号说明段。
- 步骤收束于"输出/效果"（"实现计算结果的全局收敛"）。

**3 效果**："通过上述设计方案，本发明可以带来如下有益效果：……"。有益效果必须与技术方案逐项对应（方案里的有限元建模+介电响应+优化求解 → 效果里的"定量评估"），不得出现方案中不存在的技术要素。禁止营销化程度副词（"大幅""革命性"），用"提高迭代效率、降低测试误差的扰动性"式的机制性表述。

### 2.5 附图说明

每图一行："图N [图类型]：流程图 / 模型示意图 / 划分示意图 / 接线示意图 / 曲线"。方法类专利至少含**流程图**（对应步骤一～N）；示意类图对应实施例中的结构描述。图号在实施方式中必须逐一引用（"由附图1～5所示"）。

### 2.6 实施方式

三部分：
1. **步骤重述**：与技术方案逐字高度一致（专利实务惯例，样本两节七步完全同文）；
2. **具体实施例**：给真实参数（电压等级、尺寸 4665 毫米、57 层电容屏、总电容 463 皮法、载流量、环境温度），分步演示方法如何落地；**验证数据是交底书的说服力核心**——本发明计算结果（聚合度 920/870/…）与独立手段实测（解体粘均聚合度法 950/900/…）逐项对照，量化"准确度较高"；
3. **兜底段**（固定句式）："显然，上述所描述的实施例仅是本发明的一部分实施例，而不是全部的实施例。基于本发明中的实施例，本领域普通技术人员在没有做出创造性劳动前提下所获得的所有其他实施例，都属于本发明保护的范围。"

## 三、与流水线的对接

- **证据边界**：背景技术走 stage1/2 正常检索（先行技术、事故统计、标准）；实施例数据来自用户提供的试验/仿真结果，无来源的数值一律 `[待内部确认]`，**不得虚构验证数据**（编造对照实验数据 = 硬性禁止的 fabrication）。
- **最低来源**：背景技术先行技术 ≥8（见 SKILL.md 下限表）。
- **阶段 6 专项检查**（第 16 条）：名称范式、目的-收敛句呼应、步骤依赖链完整、参数范围化、有益效果-方案对应、实施例含验证对照、附图引用闭合、发明内容/实施方式无 [Sx]、兜底段存在。
- **图**：流程图优先 Mermaid（导出管线已支持渲染）；结构示意图可留占位说明由用户补图。

## 四、反模式（常见退稿/降质写法）

- 背景技术只写"现有技术有缺点"不分类、不指向同一瓶颈 → 收敛无力。
- 技术方案步骤无依赖链（各步骤可任意调序）→ 缺乏"顺次进行"的必要性。
- 参数只给单点值 → 保护范围被无故窄化。
- 有益效果出现方案中不存在的机制 → 效果无支撑。
- 实施例无验证数据或验证无独立手段对照 → "准确度较高"断言无据。
- 发明内容/实施方式混入 `[Sx]` 或学术引用 → 法言法语被污染，新颖性表述被弱化。

## 五、申请草案模式（patent_application，四件套格式）

当用户目标是**发明专利申请草案**（含权利要求书的正式申请文本）而非交底书时，采用四件套结构，全文法言法语、**零 [Sx] 标记**：

1. **头部**：发明专利申请草案 / 发明名称 /（申请人/第一发明人注记）/（技术秘密注记，如"仅泛引基线参考模型，不披露拟合系数"）。
2. **权利要求书**（编号 1..N 连续）：
   - 权 1 独立系统权利要求："一种……系统，其特征在于，包括相互通信连接的[模块枚举]；其中：所述[模块]用于……"逐模块定义功能；
   - 权 2..k 从属权利要求（数据模型范式）："根据权利要求 n 所述的系统，其特征在于，所述[模块]所维护的数据模型包括：表名(english_table_name)，字段含……；上述各表通过[关联键]关联"；
   - 方法权利要求："一种……构建及……方法，应用于权利要求 1 至 k 任一项所述的系统，……包括以下步骤：S1、……；S2、……"；
   - 收尾存储介质权利要求："一种计算机可读存储介质，其上存储有计算机程序，所述计算机程序被处理器执行时实现权利要求 m 所述的方法。"
3. **说明书**五节：技术领域（"本发明涉及……技术领域，具体涉及……"）/ 背景技术（对象重要性→现有技术不足(1)(2)(3)(4)→技术秘密说明段，**不带引用**）/ 发明内容（"本发明要解决的技术问题是"+技术方案+有益效果(1)-(4)）/ 附图说明（"图N为本发明……"句式）/ 具体实施方式（技术栈、四层架构、数据表逐表列字段、①②③圈号流程、引擎实现、通用模块）。
4. **说明书摘要**：一段式，复述系统构成+核心机制+效果。

**与流水线的对接差异**：草案正文零标记 → 引用闭合校验移至配套文件 `12_背景技术证据对照.md`（背景断言→[Sx] 映射表 + build_references 生成文献表，不随申请提交）；正文深度门直接对草案全文执行；stage6 第 16 条对草案改查：权利要求编号连续性、独立→从属→方法→介质四段式、说明书五节齐全、摘要存在、技术秘密注记存在。
