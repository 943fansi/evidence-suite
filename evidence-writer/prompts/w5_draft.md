## Proposal Mode 边界

这是 **Proposal Mode**（表达阶段）。Research Mode（w2–w4）已经完成证据审计和诚实评估。

**提案模式铁律**：
1. 只能使用 04_validated_sources.json 中的资料。**不得新增 Research Mode 输出的证据边界之外的任何事实**。

## 硬性约束
1. 只能使用 04_validated_sources.json 中的资料。
2. 不得自行新增外部事实。
3. 不得编造政策、标准、论文、案例、市场数据、供应商参数。
4. 正文中的外部依据必须使用 [S1]、[S2] 形式引用。
5. 每一个政策依据、技术趋势、案例数据、市场数据、设备依据、标准依据都必须引用。
6. C 类资料不得作为核心立项依据。
7. 工程/设备类资料只能写为"候选选型"，不能写成唯一确定选型（教育/社科类该条可忽略）。
8. 如果资料不足，必须写入"需补充调研清单"，不得脑补。
8a. **专利类文档**（w1 选定 `patent_disclosure.md` 时）：先 Read `${SUITE_ROOT}/shared/references/patent_writing_guide.md` 并遵循其七节结构——`[Sx]` 仅限背景技术节（提交代理前由代理人剥离），发明内容/实施方式禁止引用标记；实施例验证数据无来源时标 `[待内部确认]`，禁止虚构对照实验数据；"技术路线图"节替换为方法流程图（Mermaid，步骤一→N），不要求 3/3/3 骨架；参考文献节仍机械生成（`build_references.py`），供代理人核查先行技术。

## 推理链暴露要求

对 P1-P3 和 T1-T3 对应的关键主张（从 06_evidence_map.json 的 claim_decomposition 中获取），在正文中暴露推理链：

- **格式**: 在段落末尾或中间，使用内联标注暴露 Observation → Interpretation → Assumption → Claim → Confidence 五层结构（参见 `${SUITE_ROOT}/shared/references/claim_evidence_layer.md`）。
- **最低要求**: 每个 P/T 对应的核心段落至少有一处推理链暴露。
- **示例**:
    ```
    项目具备产业化潜力。[S3]
    > 推理链: [O: S3 市场增长率23.5%] → [I: 需求增加]
    > → [A: 本领域同步] → [C: 产业化潜力]
    > Confidence: medium | Counter: 技术门槛[S5] | Unknown: 客户支付意愿
    ```

## 反方证据可见性

对 evidence_map 中 counter_evidence.evidence_against 非空的 claim，在正文相关段落中必须引用反方证据，不得只呈现支持性证据。格式：
    ```
    （需注意，[Sy]指出X条件下该方法的Y局限，本项目通过Z机制缓解此局限，但在W条件下该局限仍然存在[假设]。）
    ```

写作风格：
1. 论文主体以连贯的学术散文段落撰写，禁止将各级标题下变为要点罗列或分点堆砌。段落之间应有清晰的论证递进，一个自然段表达一个完整的论证步骤。
2. 每个理论的选用必须有明确的叙事理由——不是"本文以X理论为基础"就结束了，而是要说清楚：为什么用X而不是Y，X提供了Y缺少的什么具体机制或操作把手。这个理由应在该理论首次被引用时给出，后续使用不再重复。
3. 研究意义部分必须以真实矛盾为起点，禁止使用以下模板句式：
   - "拓展了X的理论边界"
   - "丰富了Y的应用场景"
   - "可为Z提供参考"（及其变体如"具有重要的参考价值"）
   - "填补了X的空白"（除非能引用确切来源证明该空白确实存在且本文确实填补了）
4. 实践意义需命名一个具体用户角色（如某个岗位/职业/用户群体，示例："基层单位的技术负责人""县一级学校的管理人员"），引用该角色真实困境的行业调查或研究数据（[Sx]引用），并解释为什么现有工具/培训/政策没有解决这个痛点。
5. 如果证据地图中任何关键问题与证据缺口语义匹配（即核心主张正是研究缺口本身），写入前读取 ${SUITE_ROOT}/shared/references/gap_adjacent_strategy.md 和 ${SUITE_ROOT}/shared/references/significance_writing_guide.md，按邻接拼接策略构建论证骨架，并在线索主张上标注[假设]。
6. 核心理论主张（涉及领域核心理论/模型/方法等基本概念的定义和原理解释）应优先引用标记了 `pdf_text_extracted: true` 的来源，并在正文中给出直接的原文引述（带引号 + [Sx] 标注）。搜索代理生成的 evidence_points 可用于支撑实证数据、政策条款和事实性信息，但不得用于定义或解释关键理论概念——这些必须来自经过原文 PDF 抽取确认的文字。
