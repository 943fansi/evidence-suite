# w6: Revision（修订，写作者侧 · 全局阶段 7）

> 服务对抗协议：本阶段仅按审核方 `10_review.md`（初稿审查）的判决定向修订。只修观察到的失败，不顺手重写。

**Agent**: 本地执行（当前 assistant）· 本 skill（evidence-writer）
**Input**: `10_review.md` + `08_初稿.md`
**Output**: `11_定稿.md`

## Prompt Template

```
请根据 10_review.md 修订 08_初稿.md，输出 11_定稿.md。

要求：
1. 只修订审查报告指出的问题，逐条响应，不得顺手重写无关部分。
2. 不新增未经 JSON 支撑的外部事实。
3. 保持引用闭环；所有 [Sx] 引用保持编号一致；若删/增引用须同步检查参考文献清单（推荐重跑 build_references.py --body）。
4. 对证据不足的地方降级表达或移入"需补充调研清单"。
5. 审查中标记为"阻断"的 high-severity 问题必须清零后才能进入下一阶段；清零后输出响应说明表。

响应说明表（必须输出，追加在文档末尾或单独交付）：

## 审查意见响应说明
| 意见严重程度 | 审查意见摘要 | 修订处理 | 修改位置 | 备注 |
修订处理取值：已修改 / 已降级表达 / 已移入补充调研清单 / 资料不足暂不写入正文 / 保留原表述并说明理由
```

## 可选子步骤 7b：humanizer 文风修复

仅当用户显式启用时执行：

1. 加载 `humanizer` skill（加载失败则跳过并告知，不阻断交付）。
2. 仅润色正文散文，去除 AI 腔（堆砌、空泛、促销式表达、空洞意义、规则三连、假展望）。
3. **硬边界**：不改动 `[Sx]`/`[Gx]`/`[假设]`/`[待内部确认]`/`[待验证]` 标记、参考文献与 URL/DOI、数字/单位/区间/标准编号/型号/人名/日期、Mermaid 代码块、表格结构（单元格散文可润色）、公式。不新增任何事实。
4. 数值区间 en dash（30–55 km、2021.01–2024.12）必须保留。
5. 学术文体例外：本流水线产出学术/技术文档，仅采用 humanizer「去除 AI 腔」规则；「个性化/口语化」部分不适用，不得把正式学术语言改得口语化。
6. 完成后在工作区写 `.w7_humanizer.DONE`（或用户决定跳过时写 `.w7_humanizer.SKIPPED`），供门禁识别。
7. 校验：改写后重跑引用闭合检查，确认无新增 orphaned、反营销触发词命中仍为 0；任一失败则回退改写。

## 对抗交接

修订完成后，`11_定稿.md` 提交审核方 r5 外部专家评审（用户要求时）；评审意见回到 `12_外部专家意见.md`，进入 w8 专家修订。对抗最多 2 轮，超限按审核方"终止意见"上报。
