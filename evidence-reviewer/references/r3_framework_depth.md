# r3: Framework Depth Gate（框架深度门，审查者侧 · 全局阶段 5b）

> 框架类文档（学位论文 / 实施方案 / GF 报告 / 白皮书）评审常以「只有框架、缺乏实质展开」退稿——单个 Mermaid 图 + 两段话的章节等于"目录式提纲"。本门在作者提交 `08_初稿.md` 后、r4 初稿审查前运行。

**Agent**: 本地执行（当前 assistant）· 本 skill（evidence-reviewer）
**Input**: `08_初稿.md`
**Output**: `check_framework_depth.py` 报告；通过则并入 `10_review.md`（r4）"脚本门禁结果"表，阻断则单独落盘 `03_framework_depth.md`（或直接在对抗交接中退回），无需等待 r4

## 执行步骤

1. 运行脚本：`python ${SUITE_ROOT}/shared/scripts/check_framework_depth.py 08_初稿.md`
2. 脚本对每个实质章（排除绪论/总结/摘要/致谢）检查**四要素骨架**是否展开：
   - **目标** / **方法**（手段/活动/措施/技术路线）/ **输入输出**（输入/输出/流程/步骤）/ **标准依据**（标准/规范/依据/导则/规程）
   - 并检查章节篇幅（非空白字符 ≥ 默认 1200）。
3. 结合脚本结果**人工核查**（脚本无法覆盖的）：
   - 四要素是否写成独立 `###` 小节，而非一句话带过或要点罗列。
   - 是否"一张图 + 两段话"式空框架章。
   - 学位类补充"实证算例"工作量核查（有无可复现算例 + 数值曲线图）。

## 判决规则

- **通过**：每个实质章四要素齐全 + 篇幅达标 + 无空框架章。
- **⛔ 阻断**：任一实质章**缺失 ≥2 个要素**或**篇幅低于下限** → 判决"退回 w5 展开"，要求作者把每个框架要素写成独立 `###` 小节后重新提交。

## 输出

- **通过**：将门禁结果（每章四要素矩阵 + 篇幅 + 判定）并入 `10_review.md`（r4 初稿审查）的"脚本门禁结果"表，并在总体判决中体现。
- **阻断**：本门在 r4 之前运行，此时 `10_review.md` 尚未生成——单独落盘 `03_framework_depth.md`（或直接在对抗交接中给出 ⛔ 退回判决），要求作者把缺失要素写成独立 `###` 小节后重新提交，无需等待 r4。
- 学位类若缺实证算例，按 high 优先级问题列出。
