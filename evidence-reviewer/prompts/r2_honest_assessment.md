# r2: Honest Assessment（诚实性自评，审查者侧 · 全局阶段 4b）

> w4（证据图谱）完成后的强制子步骤，在 w5（起草）之前执行；专门识别"过度宣称"。

**Agent**: 本地执行（当前 assistant）
**Input**: `06_evidence_map.json` + `04_validated_sources.json`
**Output**: `07_honest_assessment.md`

## Purpose

这是 Research Mode 的最终产物。它的目标不是"帮用户论证项目值得做"，而是"诚实地暴露证据态势"。

**允许得出的结论**:
- 证据充分，可以进入 Proposal Mode
- 证据不足但仍可论证（需标记哪些主张缺乏证据）
- 关键证据缺失，建议补搜后再进入 Proposal Mode
- 现有证据不支持立项，建议终止

## Prompt Template

```
请读取以下文件：
1. 04_validated_sources.json
2. 06_evidence_map.json

主题：{topic}
目标文档类型：{target_document}

你是独立评审专家（非项目申请方），请基于现有证据进行诚实评估。

## 硬性约束

1. **不得新增外部事实**。只能基于 04_validated_sources.json 和 06_evidence_map.json 中的已有信息。
2. **不得美化证据**。如果证据弱，请说弱；如果证据缺失，请说缺失。
3. **不得预测未来**。不要写"预计本项目完成后..."之类的推断。
4. **诚实原则**: 如果证据不支持关键主张，明确说出来。

## 评估维度

### 1. 核心主张根据是否充分

对 evidence_map 中的每个 key_problem (P1-P3)，逐条评估。

> **判定依据是 `source_support_levels`（证据直接度）与 `evidence_status`（证据状态），不是"正文里有没有 [Sx]"**。一条仅由 `weak_inference`/`context_only` 支撑、`evidence_status=inferred/unsupported` 的 claim，即使挂了 `[Sx]`，也算"证据弱"。
> **风险分级**：R3/R4（监管/安全/财务/关键结论）主张须有 primary source + 现行性 + live 回源，且来源 `authority` ≥ A2（标准/监管）；缺任一即降为高风险缺口。R1/R2 不强制回源，D1/D2（厂商/二手）作 R3/R4 依据即降级。

| 关键问题 | 证据支持度 | 直接度（direct / weak_inference / …） | evidence_status | 核心弱点 | 是否可通过邻接领域补强 |
|----------|-----------|------------------------------|-----------------|---------|---------------------|
| P1: ... | strong/medium/weak | direct/weak_inference/… | supported/partially_supported/… | ... | yes/no（如何补强） |

### 2. 反方证据权重（counter-evidence）

汇总 counter_evidence 字段中的 evidence_against 和 unknown。**凡 `source_support_levels` 中出现 `contradictory` 的来源，必须进入 evidence_against 汇总，不得遗漏或淡化。**

| 反方证据来源 | 反对什么主张 | 严重程度 | 能否在提案中回应 |
|-------------|-------------|---------|----------------|
| [Sx] | P1/P2/P3/某技术主张 | critical/high/medium | yes/no（如何回应） |

并对每条核心 claim 核对 `reconciliation.verdict` 是否与反证权重一致：存在 direct 反证却判为 `supported`、或可回应反证却判为 `contradicted`，须标记为"调和错误"并要求写作者重做。

### 3. 整体不确定性暴露

列出所有 confidence ≤ medium 的关键主张，按不确定性来源分类：

| 不确定性类型 | 涉及主张 | 是否可降低 | 降低路径 |
|-------------|---------|-----------|---------|
| 数据缺失 | ... | yes/no | 补搜/实验/引用 |
| 假设未验证 | ... | yes/no | ... |
| 因果未建立 | ... | yes/no | ... |

### 4. 证据缺口严重性分级

| 等级 | 定义 | 当前缺口 |
|------|------|---------|
| 阻断性缺口 | 核心主张无任何证据支撑 | ... |
| 高风险缺口 | 证据弱但可通过邻接拼接补强 | ... |
| 可接受缺口 | 非核心主张证据弱 | ... |

### 5. 进入 Proposal Mode 建议

结论只能为以下之一：

| 建议 | 条件 | 进入 Proposal Mode 的注意事项 |
|------|------|------------------------------|
| ✅ 可以进入 | 无阻断性缺口，高风险缺口≤1 | 按 evidence_map 约束正常写作 |
| ⚠️ 条件进入 | 有高风险缺口但可通过邻接拼接 | 所有邻接拼接主张必须标注[假设]，confidence ≤ low |
| 🔄 需补搜 | 有阻断性缺口但可定向补搜 | 补搜清单 + 重新评估 |
| ⛔ 不建议进入 | 多个阻断性缺口且不可补 | 诚实告知用户证据不支持当前方向 |
```

## Interaction Rule

本子步骤为**强制**：w4 完成证据图谱后立即执行，不得跳过。

- 若评估结论为 ⛔: 停止管线，报告用户，不进入 w5。
- 若评估结论为 🔄: 停止管线，输出补搜清单，等待用户提供新资料后重新评估。
- 若评估结论为 ⚠️: 继续管线，但将评估报告中的约束条件传递给 w5 的 prompt。
- 若评估结论为 ✅: 正常继续。

在进入 w5（Draft）前，将评估报告的核心约束摘要注入 w5 的 prompt 中。
